# The choke-point capability theorem (2026-11-06)

A statement about the capabilities that `breadstuffs/sel4/chokepoint.system` actually distributes.
It is checked over the Microkit tool's own CapDL output (`--capdl-json`), the spec seL4's CapDL
initialiser builds the image from. It is not checked over the XML.

- `SystemCaps.lean` defines the CapDL model and the authority walks (VSpace through page tables,
  CSpace through CNodes). `chokepointCaps` is the property.
- `ChokepointSpec.lean` and `ChokepointMutant.lean` are generated by `gen.sh` with
  `capdl_to_lean.py`, a transliteration with no semantic reduction. The mutant is the same system
  with persist also mapping `nic_mmio`.
- `ChokepointCapTheorems.lean` holds the theorems, all proved by `decide +kernel`:
  - `chokepoint_caps`: only commit maps the NIC window or can invoke IRQ 79's handler, and it
    does both. Only persist maps the log, and it maps it writable. Only commit and persist hold
    persist's endpoint.
  - `mutant_fails`: the falsifier, built by the real tool.
  - `three_threads`: the quantifier ranges over commit, monitor and persist.
  - `persist_can_wait_on_nic_irq`: a finding. Microkit 2.2.0 gives persist a Read-right cap on
    commit's notification, which is the object the NIC IRQ signals. Persist can wait on it and
    take commit's interrupts, although it cannot touch the NIC.

Axioms: `propext`, `Classical.choice`, `Quot.sound`. There is no `native_decide`.

Run `./gen.sh --check`, which needs `make build-chokepoint` in breadstuffs/sel4, then `./check.sh`
(about 1 min).

Named residuals:
- the Microkit tool, the CapDL initialiser and the monitor are trusted;
- the statement covers the initial distribution only, and commit's PPC endpoint carries Grant;
- DMA-capable devices are not modelled;
- physical bypass paths are not covered.
